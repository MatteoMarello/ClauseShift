# Pilot plan (written and committed before any pilot was run)

Status: **exploratory**. These pilots use the dev family (`vehicles`) and the existing test families, which have
already been analysed. They can generate or kill hypotheses; they cannot confirm them. Confirmation requires the
protocol in `EXPERIMENT_PROTOCOL.md` on newly written families.

## Pilot 1 — "Lazy reader" sanity check for occlusion evidence (no training, no model)

A deterministic program reads only the document text. It predicts `insufficient` if no Article-1 sentence states the
claimed obligation; otherwise it predicts "required" (or "not required" for a negated obligation) and maps this
through the claim polarity. **It ignores every condition, exemption and cross-reference.**

Predictions fixed in advance:
- P1a. Its flip-pair accuracy is far below the fine-tuned models' (it can solve only negation and topic_swap pairs).
- P1b. Under the registered occlusion protocol (300 correctly answered entailed/contradicted test items), its hit@1
  is 1.00, i.e. at least as high as every neural model.
- P1c. In the counterfactual removal test, its agreement on *decisive* removals is 0.00 (it never changes its answer
  when a decisive condition is removed).
Reading: if P1b and P1c hold, the registered evidence metric certifies a reader that uses no condition at all, and
the counterfactual test rejects it.

## Pilot 2 — Do minimal pairs teach the edited token instead of the rule? (cross-reference probes)

Background (audit A6): in all ClauseShift splits, every cross-reference sentence names the case's own category, so
the label of a cross-reference item is a deterministic function of "refers to Article 1" and the claim polarity.
Within a cross-reference minimal pair the only difference is the digit ("Article 1" vs "Article 2").

Probe set (new items, dev family `vehicles`, non-reserved templates, generated by
`research_next/scripts/make_probes.py`): 200 base cases whose documents satisfy all conditions, each rendered as
- `base`: no exemption;
- `xref_case_art1`: + "Article 1 does not apply to <case category>" → label flips (construction seen in training);
- `xref_case_art2`: + "Article 2 does not apply to <case category>" → label unchanged (seen);
- `xref_other_art1`: + "Article 1 does not apply to <another category>" → label unchanged (**never seen**);
- `inline_case`: + inline exemption of the case category → label flips (seen);
- `inline_other`: + inline exemption of another category → label unchanged (seen as a near miss).

Models: `cross-encoder/nli-deberta-v3-xsmall` and `microsoft/deberta-v3-xsmall`, each fine-tuned under the paired and
the unpaired condition with seed 0 and the registered recipe (re-training; weights kept locally, never committed),
plus the four zero-shot models for reference. Re-trained runs are first checked against the stored test predictions
of the same configuration (reproduction).

Primary quantity: **false-flip rate** on `xref_other_art1` = share of base cases (answered correctly on `base`)
whose prediction changes when the irrelevant cross-reference is added. Control: the same rate for `inline_other`.

Predictions fixed in advance (hypothesis S, "edit-token shortcut"):
- S1. For fine-tuned models, the false-flip rate on `xref_other_art1` exceeds 0.5 while that on `inline_other`
  stays below 0.1.
- S2. The false-flip rate on `xref_other_art1` is higher after paired than after unpaired training, for both
  initialisations.
- S3. Accuracy on `xref_case_art1` is high (> 0.8) for the NLI-initialised models.
Falsification: if the false-flip rate on `xref_other_art1` is below 0.2 for the fine-tuned models, the shortcut
hypothesis is rejected for this construction, and the in-distribution cross-reference accuracy can be read as
category-sensitive.
With one seed per condition, S2 is descriptive; it decides whether a confirmatory study is worth running, nothing
more.
